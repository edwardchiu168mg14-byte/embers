## Findings

### F1 Major — protection is per-pid, not per-subtree: children of protected processes land in actionable `pids`
`crates/embers-core/src/rules/mod.rs:151-172` (`descendants` walks THROUGH protected nodes; `tree` only drops the protected node itself). Used by E1 (e1_idle_session.rs:59-65), E2/E3/E4 (`tree(p.pid)`).
Repro (fixtures in fx/):
- a1_allowlisted_child_grandchild: idle session 100 -> allowlisted devserver 110 (config allowlist pattern "devserver") -> worker 111. Output: `100 IdleSession TerminateGroup pids=[100,111]`. 110 excluded, its worker 111 is ended -> the user's allowlisted server is crippled.
- a2_nested_busy_session: idle session 100 -> Busy session 120 (BusySession protected) -> helper 121. Output: `pids=[100,121]`: helper of a Busy session ended.
- a3c_frontmost_descendant: frontmost app 301 (child of session 100) -> 302. Output `pids=[100,302]`: child of the frontmost app ended.
- a7_notowned: session -> sudo(uid 0, NotOwned) -> node(uid 501). Output `pids=[100,111]`.
- a16_linux_sysd: session -> Xorg (protected name) -> node. Output `pids=[100,111]`.
Impact: S11/spec "never feed protected to terminate" is only literally met (protected pid itself never listed); in effect killing the protected process's own subtree breaks it. Suggested fix: do not traverse beyond a protected node (stop BFS at protected), or drop the whole ember's offending branch.
Test gap (see F9): mutation removing the filter in `tree()` leaves 17/17 tests green.

### F2 Major — URL userinfo credentials survive redaction (CLI text and --json)
`crates/embers-core/src/redact.rs:18` (inline_secret needs a keyword in the NAME), `:30` (bare_token prefix class lacks `/`).
Repro (argv element -> recovery_hint output, E2 fixture fx/red.json):
- `https://user:SECRETVAL13@example.com/x` -> unchanged
- `postgres://admin:SECRETVAL14@db:5432/app` -> unchanged
- `DATABASE_URL=postgres://u:SECRETVAL16@h/db` -> unchanged (name has no keyword)
- `https://ghp_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa@github.com/o/r` -> unchanged (PAT as URL username; `/` precedes the token so bare_token does not fire)
- `--url=https://x/sk-SECRETVAL31abcdefgh` -> unchanged
Fix direction: mask `scheme://user:pass@` password (and user when token-shaped), regardless of name.

### F6 Minor — E1 process-group path has no guard on pgid 0/1 and includes unrelated same-pgid processes
`e1_idle_session.rs:45-60`.
Repro a13_pgid0: session pgid=Some(0) + unrelated `vim` pgid 0 -> `TerminateGroup pids=[100,300]`. 1c's killpg(0) means "caller's own group" (would signal Embers itself). a3b_pgid_unrelated: unrelated vim sharing the pgid is included (by design of group kill, but not a descendant). ### F8 Minor — control-ish Unicode passes CLI output; --json emits raw C1/bidi

## Lessons
- Per-pid protection checks look complete in review of `is_protected` but the invariant that matters is per-subtree; ask "what does the BFS walk through?".
- Fixture tests that assert only `pids.contains(protected)` cannot see subtree harm; assert on the full pid set for fixtures with protected intermediates.
